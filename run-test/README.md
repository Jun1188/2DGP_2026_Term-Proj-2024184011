# 윷토체스 pico2d run-test

실제 pico2d 창으로 플레이·장면별 수동 확인을 하는 Python 시험 구현이다. HTML을 여는 래퍼가 아니다. 규칙은 `engine.py`, 화면은 `app.py`, 장면은 `scenes.py`, 레이어 데이터는 `view_model.py`로 분리했다. 시드 20261109로 Windows 창에서 업기 체험과 기본 덱 1-1을 플레이했다. 1-2에서 상점 구매 윷을 뽑아 던지기까지 확인했고, Python 단위 테스트 37건이 통과했다. [첫 3턴 체험](../docs/yutochess-revised-design.md#첫-3턴-실행-기록) · [기본 덱 완주와 다음 라운드 기록](../docs/yutochess-revised-design.md#실제-런-1라운드-완주-기록)

## 실행 (사용자 실행)

Python 3.10 이상과 pico2d 1.5.1이 필요하다. 아래 명령은 `run-test` 폴더에서 Python 3.13을 쓰는 예시다. 다른 환경에서는 `py -3.13`을 pico2d를 설치한 Python 명령으로 바꾼다.

```powershell
py -3.13 -m pip install -r requirements.txt
py -3.13 main.py
py -3.13 main.py --scene boss:combat --seed 20261109
py -3.13 main.py --list-scenes
```

이미 해당 Python에 pico2d가 설치돼 있으면 설치 명령은 생략한다. 기본 창은 1280×900이다. 한글 글꼴은 시스템 맑은 고딕/Noto를 찾는다. 글꼴이 없으면 `--font "한글.ttf 경로"`를 지정하거나 본인이 사용할 수 있는 TTF를 `assets/font.ttf`로 넣는다. 글꼴은 저작권상 복사하지 않았다.

## 조작

- 왼쪽: 장면 목록 이전/다음, 장면 선택, 7개 레이어 토글. 장면을 바꾸면 상태를 초기화한다.
- 맨 오른쪽 아래 덱을 눌러 **윷 뽑기 → 손패 공개 → 4개 선택 → 던지기** 순으로 진행한다. Space는 현재 단계의 버튼과 같다. 카드의 ‘새 윷’과 ‘남은 윷’ 표시로 이번에 뽑은 윷을 구분한다. 숫자 1~6으로 선택하거나 해제하고 R로 선택한 윷을 교체한다.
- 보드 옆 투척 결과에 네 윷의 배·등과 표시 윷, 도착점, 윷 성장식을 표시한다. 선택한 말에 금색 테두리가 생기며 업기는 두 말이 같은 칸에 닿을 때 보인다.
- 갈림길에서는 마우스를 올리거나 숫자 1·2를 눌러 경로를 비교한다. 버튼 클릭 또는 숫자로 고른 뒤 Enter로 이동을 확정한다. Esc로 미리보기를 닫는다. 단일 경로는 투척 뒤 자동 이동한다.
- 기본 업기 체험은 첫 세 턴에 도→걸→모가 나오며 4턴부터 시드 난수를 쓴다. 실제 런은 첫 턴부터 난수다. 오른쪽 투척 설정에서 수동으로 결과를 바꾸면 선택한 설정을 쓴다. 보스 윷은 항상 난수이며 빽도 고정에는 표시 윷이 필요하다.
- 편집 ON: 대상을 순환해 weight·추가 HP/공격 배율·일반 보스 시야를 +/-로 조정한다. 보드 칸 클릭으로 대상을 옮긴다. 편집 중에는 진행하지 않는다.
- 상점: 상품 구매·적용할 말 선택·말 강화·윷 강화/삭제/판매. 하단 보유함에서 출전 윷을 선택한다. 상품은 구매 후 자동 출전하지 않는다.
- F5: 상태·시드·난수·레이어를 `saved-scene.json`에 저장한다. 이 파일은 진단 증거용이며 불러오기 UI는 제공하지 않는다.
- 경로 미리보기가 닫힌 상태에서 Esc를 누르면 종료한다. ‘동작 줄이기’를 켜면 드로우·투척·말 이동·점수 모션을 생략하고 같은 결과를 즉시 표시한다. 효과 토글은 점수 이미지에만 적용한다.

## 별도 진단도구

[DIAGNOSTICS.md](DIAGNOSTICS.md)의 명령으로 레이어·기능·단계·라운드를 나눠 실행한다. `diagnose.py`는 기본적으로 창을 열지 않으며 `unittest`와 JSON 결과를 사용한다. `--visual`을 명시할 때만 pico2d 화면 진단을 연다. 전체 단위 테스트는 `python -B -m unittest discover -s tests -v`로 재실행한다.

```powershell
py -3.13 diagnose.py --list
py -3.13 diagnose.py --group features
py -3.13 diagnose.py --layer bosses
py -3.13 diagnose.py --round 1-3
py -3.13 diagnose.py --visual --scene boss:detect
```

## 포함 범위와 차이

- 현재 HTML 1.7 데이터 사본을 사용한다. 특수칸 5종, 일반 칸 +10/-5, 보스 시야·고정 대상 추적·랜덤 윷·선공/반격, 업기·완주·보상·상점·다음 라운드·확장판을 Python으로 옮겼다.
- 덱·기본 윷·전투 기물은 원안 콘셉트로 제작한 PNG로 표시한다. [게임 화면](../docs/detailed-design/img/pico-third-turn.png) 원본 HTML CSS/웹 UI를 그대로 재현한 것은 아니다. 현재 점수 이미지에는 pico2d에서 색 필터를 적용하지 않고 방향·회전·확대·투명도로 구분한다.
- 순수 Python 코어와 HTML 코어는 별도 구현이다. 체험 첫 세 턴에서 경로·HP·보유점수의 일치를 확인했다. 전체 런의 균형은 추가 측정 대상이다. JS와 Python의 부동소수점 경계에서 차이가 날 수 있다.
- HTML 장면 JSON과 호환하지 않는다. HTML의 임의 UI 좌표 편집과 장면 JSON 불러오기는 이 시험본에 없다. 확률 표·덱 특성 강화/삭제·말 특성 삭제·출전 상한 확장은 제공한다. 상점 오른쪽 상품/빌드 관리 전환 버튼을 사용한다. 기존 최소 출전 4개를 맞춰 다음 라운드로 진행한다.
- `game-data.json`과 `assets/`의 게임 리소스는 이 폴더에 함께 둔다. 상위 폴더·브라우저·개인 절대 경로에 의존하지 않는다. HTML 데이터 변경은 자동 동기화하지 않는다.

정식 제출·최종 배포본으로 확정하지 않았다. 원격 업로드·Public 설정·원격 커밋 수·e-Class 제출은 이번 작업에서 확인하지 않는다.

## 점수 강조 확인 (2026-11-11, 사용자 실행)

점수 강조는 합계 차이 대신 개별 변동 내역을 사용한다. 일반 칸·특수칸·업기·전투·판 전체·빅 기믹·완주 성장마다 보유점수판이, 완주 정산에서는 완주점수판이 강조된다. 각 변동은 0.65초 간격으로 0.6초씩 재생한다. +와 -가 상쇄돼도 각각 표시하며, 빠르게 다음 행동을 하면 남은 강조 뒤에 이어서 재생한다. 장면·라운드 전환 시 이전 효과는 지운다.

위 장면들을 실행해 점수판의 출처·부호·색·테두리·숫자/이미지 효과를 확인한다. 이미지 효과 OFF에서도 숫자 강조가 남는지, 동작 줄이기에서 모션이 생략되는지 확인한다. +0 효과는 점수 변화 내역으로만 표시한다. 이 절은 11월 11일 기준의 점수 효과 확인 절차다.
