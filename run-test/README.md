# 윷토체스 pico2d run-test

실제 pico2d 창으로 플레이·장면별 수동 확인을 하는 Python 시험 구현이다. HTML을 여는 래퍼가 아니다. 규칙은 `engine.py`, 화면은 `app.py`, 장면은 `scenes.py`, 레이어 데이터는 `view_model.py`로 분리했다. 원본 HTML은 수정하지 않는다. 실행·테스트는 아직 하지 않았다.

## 실행 (사용자 실행)

Python 3.10 이상과 pico2d 1.5.1이 필요하다. 현재 PC에는 Python 3.13용 pico2d 1.5.1 소스가 있다. 실제 로딩/SDL 동작은 미확인이다. 아래 명령은 `run-test` 폴더에서 사용한다.

```powershell
py -3.13 -m pip install -r requirements.txt
py -3.13 main.py
py -3.13 main.py --scene boss:combat --seed 20261109
py -3.13 main.py --list-scenes
```

이미 해당 Python에 pico2d가 설치돼 있으면 설치 명령은 생략한다. 기본 창은 1280×900이다. 한글 글꼴은 시스템 맑은 고딕/Noto를 찾는다. 글꼴이 없으면 `--font "한글.ttf 경로"`를 지정하거나 본인이 사용할 수 있는 TTF를 `assets/font.ttf`로 넣는다. 글꼴은 저작권상 복사하지 않았다.

## 조작

- 왼쪽: 장면 목록 이전/다음, 장면 선택, 7개 레이어 토글. 장면을 바꾸면 상태를 초기화한다.
- 오른쪽: 드로우 → 공개 → 직접 4개 선택 → 던지기. Space도 같은 단계로 진행한다.
- 하단: 손패 선택/재클릭 해제. 선택 카드는 12px 올라간다. 1~6은 손패 키, R은 선택 윷 교체다.
- 갈림길: 보드 옆 두 경로 버튼. 마우스를 올리면 경로, 누르면 확정한다. 단일 경로는 투척 후 자동 진행한다.
- 플레이어 결과 버튼: 난수/도/개/걸/윷/모/빽도를 순환한다. 보스 윷은 항상 난수다. 빽도 고정은 표시 윷을 선택해야 한다.
- 편집 ON: 대상을 순환해 weight·추가 HP/공격 배율·일반 보스 시야를 +/-로 조정한다. 보드 칸 클릭으로 대상을 옮긴다. 편집 중에는 진행하지 않는다.
- 상점: 상품 구매·적용할 말 선택·말 강화·윷 강화/삭제/판매. 하단 보유함에서 출전 윷을 선택한다. 상품은 구매 후 자동 출전하지 않는다.
- F5: 상태·시드·난수·레이어를 `saved-scene.json`에 저장한다. 이 파일은 진단 증거용이며 불러오기 UI는 제공하지 않는다.
- ESC: 종료. 동작 줄이기는 드로우/점수 모션을 생략한다. 효과 토글은 이미지 효과만 끈다.

## 별도 진단도구

[DIAGNOSTICS.md](DIAGNOSTICS.md)의 명령으로 레이어·기능·단계·라운드를 나눠 실행한다. `diagnose.py`는 기본적으로 창을 열지 않으며 `unittest`와 JSON 결과를 사용한다. `--visual`을 명시할 때만 pico2d 화면 진단을 연다. 현재 테스트는 **작성만 한 미실행 상태**다.

```powershell
py -3.13 diagnose.py --list
py -3.13 diagnose.py --group features
py -3.13 diagnose.py --layer bosses
py -3.13 diagnose.py --round 1-3
py -3.13 diagnose.py --visual --scene boss:detect
```

## 포함 범위와 차이

- 현재 HTML 1.7 데이터 사본을 사용한다. 특수칸 5종, 일반 칸 +10/-5, 보스 시야·고정 대상 추적·랜덤 윷·선공/반격, 업기·완주·보상·상점·다음 라운드·확장판을 Python으로 옮겼다.
- 그림은 pico2d 도형·글자와 기존 GPT 이미지 PNG다. 원본 HTML CSS/웹 UI를 그대로 재현한 것은 아니다. 현재 점수 이미지에는 pico2d에서 색 필터를 적용하지 않고 방향·회전·확대·투명도로 구분한다.
- 순수 Python 코어와 HTML 코어는 별도 구현이다. 데이터는 같아도 동작 일치·균형·화면은 미검증이다. JS와 Python의 부동소수점 경계에서 차이가 날 수 있다.
- HTML 장면 JSON과 호환하지 않는다. HTML의 임의 UI 좌표 편집과 장면 JSON 불러오기는 이 시험본에 없다. 확률 표·덱 특성 강화/삭제·말 특성 삭제·출전 상한 확장은 제공한다. 상점 오른쪽 상품/빌드 관리 전환 버튼을 사용한다. 기존 최소 출전 4개를 맞춰 다음 라운드로 진행한다.
- `game-data.json`과 `assets/score-burst.png`는 이 폴더 안의 사본이다. 상위 폴더·브라우저·개인 절대 경로에 의존하지 않는다. HTML 데이터 변경은 자동 동기화하지 않는다.

정식 제출·최종 배포본으로 확정하지 않았다. 원격 업로드·Public 설정·원격 커밋 수·e-Class 제출은 이번 작업에서 확인하지 않는다. 빌드·브라우저·pico2d·단위 테스트·검증기는 실행하지 않았다. 사용자 실행 결과를 보고 조정한다.

## 점수 강조 확인 (2026-11-11, 사용자 실행)

점수 강조는 합계 차이 대신 개별 변동 내역을 사용한다. 일반 칸·특수칸·업기·전투·판 전체·빅 기믹·완주 성장마다 보유점수판이, 완주 정산에서는 완주점수판이 강조된다. 각 변동은 0.65초 간격으로 0.6초씩 재생한다. +와 -가 상쇄돼도 각각 표시하며, 빠르게 다음 행동을 하면 남은 강조 뒤에 이어서 재생한다. 장면·라운드 전환 시 이전 효과는 지운다.

위 장면들을 실행해 점수판의 출처·부호·색·테두리·숫자/이미지 효과를 확인한다. 이미지 효과 OFF에서도 숫자 강조가 남는지, 동작 줄이기에서 모션이 생략되는지 확인한다. +0 효과는 점수 변화 내역으로만 표시한다. 빌드·앱 실행·테스트·검증기는 실행하지 않았다.
