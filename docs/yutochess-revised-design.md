# 윷토체스 수정 기획서

**2026-11-09 · 기본 PvE · 과제 시연 범위는 1막 3라운드**

윷토체스는 매 턴 덱에서 뽑은 윷가락을 골라 던지고, 결과에 따라 이동할 말을 정하는 싱글 플레이 덱빌딩 게임이다. 윷의 점수·특성은 선택한 말에 귀속되어 그 말의 **weight(미정산 가치)**를 키운다. **말이 완주해야 그 말이 벌어온 weight를 라운드 점수에 더한다.** 승리 조건은 **라운드 점수 ≥ 목표 점수**이며, 목표 초과 점수와 보너스는 유지한다. 완주 개수는 별도 승리 조건으로 두지 않는다.

수문장과 보스는 **특정 길목에 상주하며 플레이어 말과 전투**한다. 주둔 칸·공격 범위·다음 행동을 공개하고, 플레이어는 진입 경로·움직일 말·업기·교전 순서를 고른다. 이 위치와 전투 판단이 SRPG 요소다. 적은 플레이어를 따라 이동하거나 윷판을 순찰하지 않는다.

## 한 턴에서 무엇을 고르는가

손패 6개에서 4개를 고를 때 나무 윷을 납 윷으로 바꾸면 ‘모’의 확률이 올라간다. 표시 윷을 빼면 빽도가 나오지 않는다. 손패를 누를 때마다 결과별 확률과 이번에 말에 귀속될 weight 증가량을 갱신한다. 사용한 윷은 버림 더미로 보내고 다음 턴에 손패를 보충한다. 덱이 소진되면 버림 더미를 섞는다.

투척 뒤에는 어느 말에 결과를 사용할지 고른다. 길목 수문장의 전투 범위에 들어가 싸울지, 다른 말을 움직여 업기를 준비할지, 누적 weight가 높은 말을 완주시킬지 판단한다. 수문장 칸에 멈추는 것만으로 적을 처치하지 않으며, 교전은 완주보다 먼저 해결한다.

HUD는 **정산된 점수/목표, 말별 weight, 남은 투척·교체, 수문장의 주둔 칸·공격 범위·다음 행동**을 보여 준다. 이동 미리보기는 도착 칸·업기·교전·완주와 해당 선택의 weight 증가량 및 완주 정산액을 구분한다. 미리보기를 여는 것만으로 자원이 소모되거나 판 상태가 바뀌지 않는다.

## weight 누적과 완주 정산

- 라운드 시작 시 각 말의 weight와 라운드 점수는 0이다.
- 족보·윷의 발동 효과·강화·시너지·부적·이동 이벤트로 이번 weight 증가량을 계산한다. 윷의 효과와 산출 값은 선택한 말에 귀속한다. 과거 투척 효과를 다음 턴에 자동 재발동하지 않으며, 지속 효과는 개별 설명의 기간을 따른다.
- 미완주 말의 weight가 커져도 라운드 점수는 변하지 않는다. 윷의 점수나 특성 자체를 라운드 점수에 직접 가산하지 않는다.
- 업기 전의 말별 weight는 보존한다. 이번 묶음 증가량에 업기 배율을 적용한 후 구성 말에 균등 배분하고, 나머지는 말 ID 순서로 1씩 준다. 기존 weight를 다시 곱하거나 복제하지 않는다.
- 완주 이벤트의 Chips 보너스도 해당 말의 weight 계산에 넣는다. 이후 완주한 말들의 weight 합계를 라운드 점수에 **한 번만** 가산하고 정산 완료로 표시한다.
- 전투 패배로 잡히면 해당 묶음은 출발 대기로 돌아가며 미정산 weight·귀속 효과·업기 배율을 초기화한다. 이미 완주해 확정한 점수는 유지한다.

예를 들어 A의 weight가 100, B가 200이고 이번 묶음 증가량이 240이면 A=220, B=320이다. 이 시점의 라운드 가산점은 0이다. 이후 추가 증가 없이 두 말이 완주하면 540점만 정산한다(완주 보너스를 제외한 귀속·정산 설명용 예시).

배분·초기화·효과 지속의 세칙은 첫 프로토타입 기준안이다. 수치는 플레이테스트로 조정한다. 세부 계산 순서는 [상세 기획서 7장](detailed-design/index.html#score), 데이터는 [1.3.0-draft](detailed-design/game-data.json)를 따른다.

## 길목 전투와 라운드 판정

1. 라운드 특성으로 목표 점수·보상 배수를 정한다. 말 4개와 길목 수문장을 배치한다. 일반 수문장은 `rules.guardianCombat.posts`의 서로 다른 지정 칸을 사용하고, 보스는 자신의 `start` 칸에 상주한다.
2. 손패 선택·교체 후 윷 4개를 던진다. 투척 1회를 소모하고 족보를 판정한다. 윷·모와 전투 승리의 추가 투척은 각각 해당 사건에서 한 번 적용한다. 이동할 말이 없는 빽도는 weight와 라운드 점수를 얻지 않는다.
3. 선택한 말에 윷의 효과를 연결하고 이동·업기·교전을 처리한다. 수문장 전투에서 승리하면 잡기 배수와 추가 투척을 받는다. 패배한 묶음은 초기화하고 해당 투척의 weight 증가도 받지 않는다. 전투를 통과한 말만 완주할 수 있다.
4. 생존한 말의 weight를 누적하고 완주한 말만 정산한다. 남아 있는 주둔 수문장의 예고된 행동을 처리한 뒤 아래 표를 위에서부터 적용한다.

| 우선순위 | 턴 정산 직후 조건 | 결과 |
|---|---|---|
| 1 | 라운드 점수 ≥ 목표 | 클리어. 초과 점수와 보너스를 유지하고 남은 투척·이자를 포함해 보상을 한 번 정산한다. |
| 2 | 목표 미달이며 투척 0회 또는 말 4개 모두 완주 | 런 종료. 남은 미완주 weight는 점수로 환산하지 않는다. |
| 3 | 목표 미달이며 투척과 움직일 말이 남음 | 손패를 보충하고 다음 턴을 진행한다. |

처치한 수문장은 2투척 뒤 원래 주둔 칸에 재등장한다. HP·공격력·방어력·사거리 수치, 피해식과 업기의 전투 보정은 미확정이다. 도깨비는 주둔지 주변 함정, 호랑이는 범위 안 고weight 말 우선 공격, 저승사자는 참먹이 직전 교전을 보스 기믹 초안으로 둔다.

초과 점수는 `max(0, 라운드 점수 - 목표 점수)`로 기록한다. 초과 달성 보너스는 유지하되 환산식·비율은 미확정이다. 기존 기본 보상·남은 투척·이자 식은 [11장](detailed-design/index.html#economy)을 따른다. 1-1·1-2 후에는 보상 → 상점 → 다음 라운드 특성 선택으로 이어지고 1-3 후에는 막 결과와 재시작을 제공한다.

## 1막에서 시연할 범위

| 구성 | 플레이어가 확인할 내용 |
|---|---|
| 윷판과 전투 | 29칸 경로, 지름길, 빽도, 업기, 길목 전투, 완주. 일반전은 고정 수문장, 엘리트는 복수 길목, 보스는 상주 도깨비와 주변 함정이다. |
| 점수 | 투척 때 말별 weight만 증가하고 완주 때 라운드 점수가 증가한다. 묶음의 기존 weight 보존, 패배 시 초기화, 중복 정산 방지를 보여 준다. |
| 덱과 상점 | 나무·표시·납 윷 3종과 까치·거북·복주머니 부적 3종을 첫 후보로 둔다. 영입·강화한 윷이 다음 라운드 손패와 weight 증가량에 영향을 준다. |
| 라운드 특성 | 정석 한 판·지름길 봉쇄·질주·낙 주의 4종을 첫 후보로 둔다. 경로·완주 가치·투척 위험을 사전에 표시한다. |
| 완료 장면 | 시작 → 1-1 → 상점 → 1-2 → 상점 → 1-3 → 막 결과 → 재시작. 실패 시에도 결과와 재시작으로 이어진다. |

## 호스트와 이후 모드

| 모드 | 호스트가 하는 일 | 승패 기준 |
|---|---|---|
| 기본 PvE | 지정 길목의 수문장·보스 전투와 기믹을 진행한다. 주둔 위치를 유지하고 공격 범위·다음 행동을 공개한다. | 완주 정산 점수 ≥ 목표 |
| 적응형 PvE (1막 이후) | 고정 주둔 위치와 공격 범위 안에서 다음 행동을 고른다. 행동 트리는 말 배치와 미정산 weight를 읽는다. | 기본 PvE와 같음 |
| 봇 대전·PvP | 상대가 자기 말을 움직인다. PvP 호스트는 입력 검증·난수·턴 순서·결과 확정을 맡는다. | 상대 점수 비교의 세부 종료 조건은 후속 단계에서 정한다. |

호스트는 손패 선택 전에 다음 행동을 확정해 공개하며, 투척 결과를 보고 예고를 바꾸지 않는다. 난수는 런 시드 하나를 사용한다. 봇 경로 탐색은 플레이어 측 경로·교전 판단에 사용한다. PvE 적의 추격에는 사용하지 않는다.

## HTML 박싱 게임과 편집기

[상세 기획서의 박싱 게임](detailed-design/index.html#boxing)에 1막 코어 루프를 구현했다. [원본 플로차트](core-loop-flowchart.png)의 메뉴·덱 세팅 → 라운드 특성 → PvE → 보상 → 상점·강화·덱 편집 → 다음 라운드 → 결과·재시작을 따라간다.

- 시작 덱 3종, 매 라운드 특성 3택 1(정석·봉쇄·질주·낙 주의 중 제시), 실제 손패·투척·이동·전투·완주 정산을 사용한다.
- 보상을 수령하면 엽전이 한 번 지급되고 상점으로 간다. 윷·부적 구매, 확률 강화, 제거·판매 후 변경한 덱을 다음 라운드에 사용한다. 세 번째 라운드 후 막 결과를 표시한다.
- 편집 모드는 턴 진행을 멈춘다. UI 패널 너비·글자 크기·강조색, 보드 시각 좌표, 말 배치·HP·weight, 수문장 배치·HP·공격력·공격 범위, 라운드 목표·투척·교체·재화를 편집할 수 있다. 보드·말·수문장의 드래그 배치도 지원한다.
- 장면 JSON은 배치·난수 상태·손패·덱·전투 상태·기록을 저장한다. 같은 데이터 버전에서 불러와 이어서 플레이한다. 파일 저장은 브라우저 다운로드이며 저장소 원본 파일을 직접 덮어쓰지 않는다.
- 임시 전투식과 초과 보너스 환산은 `game-data.json`의 `boxing` 초기값을 사용한다. 2·3막·증강·나머지 콘텐츠·pico2d 구현은 후속 범위다.

사용자 확인 절차는 [박싱 안내](detailed-design/README.md)에 정리했다. 브라우저 실행·게임 플레이·테스트·밸런스 확인은 수행하지 않았으며 사용자에게 맡긴다.
