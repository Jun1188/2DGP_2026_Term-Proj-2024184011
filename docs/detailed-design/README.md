# 윷토체스 상세 기획서와 박싱 테스트베드

`index.html`에 기획서, 계산기, 직접 플레이하는 1막 PvE 게임과 장면 편집기가 함께 들어 있습니다.

## 열기

`index.html`을 브라우저에서 직접 열고 목차의 **박싱 게임 · 플레이 / 편집**을 누르세요. HTML에 포함한 데이터 사본을 사용하므로 서버 설치가 필요하지 않습니다. 같은 폴더의 `boxing-game.js`와 `boxing-game.css`도 함께 있어야 합니다.

최신 `game-data.json`을 자동으로 읽으려면 사용자가 아래 명령을 실행할 수 있습니다.

```powershell
python -m http.server 8000 --directory docs/detailed-design
```

[박싱 게임 열기](http://localhost:8000/index.html#boxing). 로컬 파일 자동 읽기가 실패하면 HTML에 포함한 데이터로 열립니다. 데이터가 모두 손상되면 상단 파일 선택으로 JSON을 지정할 수 있습니다.

## 실제 플레이 순서

1. 메뉴에서 시작 덱 3종 중 하나를 선택합니다. 위쪽 시드를 바꾸고 새 런을 누르면 다른 난수 순서로 시작합니다.
2. 라운드 특성 3개 중 하나를 고릅니다. 목표 점수와 위험·보상 배수가 정해집니다.
3. 손패에서 윷 4개를 골라 **던지기**를 누릅니다. 교체는 선택한 윷을 버리고 보충하며 횟수를 소모합니다.
4. 결과가 나온 뒤 왼쪽의 말 버튼을 누릅니다. 마우스를 올리면 경로와 교전 예고를 볼 수 있습니다. 이동 확정 시 업기·고정 길목 전투·weight 누적·완주를 처리합니다.
5. 미완주 말의 weight는 커져도 라운드 점수는 유지됩니다. 완주한 말의 weight만 한 번 정산합니다. 목표 이상이면 보상, 목표 미달에 투척 소진/전원 완주이면 런 종료입니다.
6. **보상 받기 → 상점**을 누르면 엽전이 한 번 지급됩니다. 윷·부적 구매, 확률 강화, 윷 제거·판매를 한 뒤 다음 라운드 조건을 선택합니다. 바뀐 덱·강화·부적·엽전은 유지합니다.
7. 1-3 보스까지 클리어하면 보상 수령 후 막 결과가 나옵니다. 승리·패배 결과에서 메뉴로 돌아가 새 런을 시작합니다.

게임 영역에 포커스가 있을 때 `1~6`은 손패 선택, `Space`는 던지기, `R`은 교체입니다. 말 버튼은 키보드로도 선택할 수 있습니다.

## 편집하기

**편집 모드**를 누르면 턴 진행이 멈춥니다. 편집 대상 목록 또는 보드 위 개체를 선택하고 **변경 적용**을 누르세요.

| 대상 | 편집 내용 |
|---|---|
| UI 프레임 | 점수·수문장 패널 너비, 글자 크기, 강조색. 좁은 화면은 반응형 배치를 우선합니다. |
| 보드 칸 | X/Y 시각 좌표. 드래그도 가능합니다. 경로 연결은 그대로 유지합니다. |
| 내 말 / 업힌 묶음 | 배치 칸, HP, weight 합계. 묶음 weight는 구성 말에 나눕니다. |
| 수문장 | 주둔 칸, 최대/현재 HP, 공격력, 그래프 거리 기준 공격 범위. 드래그 시 가까운 칸에 배치합니다. |
| 라운드 자원 | 목표 점수, 투척·교체 잔여 횟수, 보유 엽전. 라운드 진행 중에 변경합니다. |

출발 대기 말은 편집 대상 목록에서 선택하세요. 말을 재배치하면 빽도용 이력을 해당 경로로 다시 만듭니다. 정산 완료한 말은 재편집 대상에서 제외합니다. **편집 종료 → 플레이**로 같은 장면을 이어갑니다.

**박싱 머신**을 펼치면 UI 프레임·말·수문장·위협 레이어를 각각 표시/숨김 할 수 있습니다. 레이어를 숨겨도 규칙 판정은 유지됩니다. 고정 투척 결과, 완주·길목 전투·투척 소진 장면도 제공하며, 장면 버튼은 별도 새 런으로 시작합니다.

**장면 JSON 저장**은 배치·UI 설정·덱·손패·강화·말·수문장·난수·진행 상태·사건 기록을 다운로드합니다. **장면 불러오기**로 같은 데이터 버전의 파일을 열면 편집 모드에서 복원합니다. 파일을 잘못 고르면 기존 장면을 유지하고 오류를 표시합니다. 저장소의 HTML·JSON은 직접 덮어쓰지 않습니다.

## 사용자 확인 항목 — 실행 전

이 작업에서는 빌드, 브라우저 실행, 게임 플레이, 자동·수동 테스트를 수행하지 않았습니다. 아래 확인은 사용자가 진행합니다.

| 절차 | 기대 결과 |
|---|---|
| 정상 새 런 → 특성 → 윷 4개 → 투척 → 말 선택 | 실제 손패·이동 결과가 바뀌며 수문장은 주둔 위치를 유지합니다. |
| 박싱 머신의 **완주·초과 보상** → 윷 4개 → 투척 → A 이동 | 미리 설정한 weight와 이번 증가분이 완주 때만 점수에 가산됩니다. 목표 초과 점수와 보너스를 표시합니다. |
| 보상 수령 → 상품 영입·강화·제거/판매 → 다음 라운드 | 보상은 한 번 지급되며 변경한 덱·강화·부적·잔액이 유지됩니다. |
| 1-2·1-3을 진행. 빠른 확인은 편집기로 말 A를 19번, weight를 목표 이상으로 배치 | 각 라운드 보상·상점을 지나 도깨비 보스 후 막 결과와 새 런으로 이어집니다. |
| **길목 전투** 장면 → A를 선택해 5번에 진입 | 공격·방어·반격·처치/재등장 기록이 남습니다. HP 소진 시 묶음과 미정산 weight를 초기화합니다. |
| **투척 소진** 장면 → 윷 4개 → A 이동 | 목표 미달로 런이 종료되며 미완주 weight를 점수로 환산하지 않습니다. |
| 편집 모드에서 보드·말·수문장 드래그 및 속성 적용 → 편집 종료 | 화면 배치와 실제 이동·전투·정산이 바뀐 값을 사용합니다. |
| 투척 직후/MOVE에서 장면 저장 → 다른 장면 → 저장 파일 불러오기 | 손패·투척 결과·말·적·시드 상태가 복원되고 이어서 이동할 수 있습니다. |
| UI 패널 너비·색·글자 크기 변경, 레이어 토글 | 화면에 즉시 반영됩니다. 저장·불러오기 후에도 유지됩니다. |
| 잘못된 장면 JSON 불러오기 | 오류를 표시하며 기존 런을 덮어쓰지 않습니다. |

## 구현 범위와 초기값

1막 3라운드, 시작 덱 3종, 사용 가능한 윷은 나무·표시·납·깃털·불꽃·대나무, 상점 부적은 까치·거북·복주머니입니다. 특성은 정석·봉쇄·질주·낙 주의 중 3개를 제시합니다. 전체 기획의 2·3막, 무한 모드, 증강, 합치기, 족보 비급과 나머지 콘텐츠는 이번 박싱에 포함하지 않습니다.

전투는 `game-data.json`의 `boxing`을 사용합니다. 말 HP 6·공격 4, 일반 수문장 HP 6·반격 2, 보스 HP 10, 일반/보스 공격 범위 0/1이 초기값입니다. 업힌 말은 공격력을 합치며 이번 기본 weight에 따른 보정을 받습니다. 적이 살아 있으면 반격 후 진입을 막습니다. 초과 600점당 1냥은 박싱용 보너스 가정입니다. 모든 수치는 사용자가 플레이하며 조정할 대상입니다.

| 파일 | 역할 |
|---|---|
| `index.html` | 기획서, 박싱 임베딩, 데이터 로더, 파일 직접 열기용 데이터 사본 |
| `game-data.json` | 규칙·콘텐츠·윷판 경로와 박싱 초기값의 작성 원본 |
| `boxing-game.js` | 손패·턴·전투·정산·상점·편집·저장/불러오기 |
| `boxing-game.css` | UI 프레임과 보드/말/수문장/위협 레이어 스타일 |
| `img/toss-screen-concept.png` | 과거 투척 화면 콘셉트 |

수치 변경은 JSON 원본에 반영하고, HTML의 `embeddedGameData` 사본도 동기화해야 직접 파일 열기에 반영됩니다. 로컬 서버에서는 JSON 원본을 우선 사용합니다. JavaScript 박싱과 Python/pico2d 구현은 별도이며 실행 결과를 상호 검증하지 않았습니다.
